Selecting a profile resets its editable activity fields and model mix. The neutral workload baseline is a 100,000–400,000-line repository and a 50–75-line pull request. Smaller repositories and narrow fixes reduce the estimate; larger repositories increase input, while broader changes increase both input and output.

Code-search assumption

Every repository-size scenario assumes efficient native indexing or a graph-aware plugin such as Graphify. This keeps large-repository adjustments to 1.1× and 1.2× rather than modelling repeated raw file reads and grep. Retrieved code still consumes input tokens, and the multipliers remain planning assumptions rather than pooled empirical averages.

What does the default 50k-token run represent?

Using OpenAI’s general rule of thumb of about four characters per token:

50,000 input tokens Approximately 200,000 characters, or roughly 2,500–5,000 lines if every character were source code.
5,000 output tokens Approximately 20,000 characters, or roughly 250–500 lines under the same all-code assumption.

These are upper-limit code equivalents, not expected patch sizes. Prompts, paths, documentation, tests, terminal output, explanations and repeated context all consume tokens. A 50,000-token context could represent around 25–50% of a 10,000-line service, 2.5–5% of a 100,000-line application, or 0.25–0.5% of a one-million-line repository.

The default ten-developer, spec-driven scenario represents 88 million input and 8.8 million output tokens each month. Its cache split is 35% reads, 10% writes and 55% uncached input. Replace these defaults with billing-export data as soon as a representative pilot is available.

Evidence behind the planning assumptions

The editable presets are evidence-calibrated planning scenarios, not observed industry averages. Token accounting also differs between tools and agent harnesses. The following original studies and first-party datasets establish the ranges used to interpret interaction size, delegated-task size, change size and repository-context overhead.

  1. Bai et al., How Do AI Agents Spend Your Money? — 1,190 tokens for code reasoning, 3,390 for code chat and 4.17 million for OpenHands agentic coding on average; repeated input context drove most agent consumption.
  2. Islam, Ali and Parvez, CodeSIM, NAACL Findings 2025 — direct prompting averaged 560 tokens, while structured planning, coding and debugging averaged 13,640 tokens and 9.3 model calls.
  3. Bouzenia and Pradel, Understanding Software Engineering Agents — mean repository-task consumption ranged from 23,000 tokens for AutoCodeRover to 220,000 for RepairAgent and 1.2 million for OpenHands.
  4. Anthropic, Agentic coding and persistent returns to expertise — first-party analysis of approximately 400,000 Claude Code sessions found about four human turns per typical session and roughly ten agent actions per prompt.
  5. GitHub and Accenture, enterprise Copilot study — developers reported using Copilot on 3.4 days per week on average; around 30% of suggestions were accepted.
  6. OpenAI, Codex rate card — first-party budgeting cross-check reporting average Codex spend of approximately $100–$200 per developer per month, with substantial variation by model, parallelism and automation.
  7. Wang et al., RepoMaster, NeurIPS 2025 — graph-guided repository exploration reduced token usage by 95% on GitTaskBench relative to the evaluated baseline.
  8. Zheng et al., CORVUS — synchronising repository context reduced average input tokens by 9–50% across two repository benchmarks.
  9. Jimenez et al., SWE-bench, ICLR 2024 — the median real-world issue changed one function and about 15 lines in a codebase of roughly 400,000 lines; the mean solution changed 32.8 lines across 1.7 files.
  10. Watanabe et al., On the Use of Agentic Coding — matched agentic pull requests changed a median 55 lines across two files, compared with 32 lines across two files for matched human pull requests.
  11. DX, telemetry from more than 400 organisations — median pull-request size increased from 44 to 72 changed lines between July 2025 and June 2026; the observational result does not establish that AI caused the increase.
  12. Ogenrwot and Businge, How AI Coding Agents Modify Code, MSR 2026 — analysis of 24,014 merged agentic pull requests found that agent changes were generally smaller and more localised than human contributions.
  13. Zhang et al., FastContext — repository reading and searching consumed a large share of agent trajectories; delegated exploration reduced main-agent tokens by up to 60%.
  14. Sourcegraph, CodeScaleBench — first-party results from 1,281 runs found local-only navigation struggled above roughly 400,000 lines and benefited most from indexed code intelligence between 400,000 and two million lines.
  15. Qiu et al., LoCoBench-Agent — evaluates software-engineering agents across 10,000 to one million tokens of relevant context and finds a material trade-off between comprehension and exploration efficiency.
  16. Cursor, Securely indexing large codebases — semantic indexing retrieves relevant code chunks, caches unchanged embeddings and reuses team indexes; Cursor reports higher response accuracy but does not publish a token-saving percentage.
  17. Cursor, Teams pricing update — model usage is charged at the underlying API rate plus $0.25 per million processed tokens, which covers code indexing, indexing models and tool execution.
  18. Graphify, open-source repository and documentation — builds a local code knowledge graph exposed through MCP to Claude Code, Cursor, Copilot, Codex, Gemini CLI and other assistants; no directly comparable token-reduction evaluation is published.
  19. Codebase-Memory, repository-graph evaluation — across 31 repositories, a Tree-sitter knowledge graph achieved 83% answer quality versus 92% for file exploration while using ten times fewer tokens and 2.1 times fewer tool calls.
